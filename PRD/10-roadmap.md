## 10. 迭代 Roadmap

### V1 → V2 升级清单

| 功能 | 优先级 | 前置依赖 | 预估复杂度 | 备注 |
|------|-------|---------|-----------|------|
| 关系困扰专属流程 | P1 | V1 证明关系状态提交率和追问率更高 | 中 | 从 BRD 判断看，关系困扰更接近付费 |
| 真实低价单次支付 | P1 | 付费意愿点击和等待名单达到阈值 | 中 | V1 只验证意愿，不接支付 |
| 多轮追问 | P1 | 用户点击继续追问且愿意提交更多问题 | 中 | 需要会话上下文和更多安全规则 |
| 真人/半人工增强解读 | P2 | 有足够等待名单和人工供给 | 高 | 当前私人咨询证据较弱，先不做 |
| 账号和历史记录 | P2 | 用户重复访问和保存行为成立 | 中 | V1 用匿名会话和本地保存 |
| 多语言切换 | P2 | 明确要扩展非泰语市场 | 中 | V1 只服务泰语用户 |
| TikTok 内容引流页 | P2 | 有具体内容账号或投放计划 | 中 | 先验证产品内闭环 |
| 社区/公开结果广场 | P3 | 有足够安全审核和内容治理能力 | 高 | 情绪敏感内容不适合 V1 公开化 |

### 长期方向

如果 V1 证明用户愿意提交长文本、继续追问并表达私人化付费意愿，产品可以从“单次占卜式陪伴工具”升级为“关系和情绪低谷时的私人化占卜陪伴入口”。长期不建议变成泛娱乐抽牌工具；差异化应继续围绕情绪承接、泰语语境和安全边界。

### 已知技术债

| 技术债 | 影响范围 | 建议解决时机 |
|-------|---------|------------|
| V1 无账号体系 | 跨设备找回结果困难 | 用户重复访问成立后 |
| V1 安全检测以规则为主 | 难覆盖所有泰语危机表达 | V2 前补充人工样本和模型分类 |
| V1 Prompt 单一 | 不同状态的语气可能不够细 | 状态数据足够后拆分 Prompt |
| V1 只记录点击意愿 | 不能证明真实支付 | 准备接真实支付前 |
| V1 本地保存依赖浏览器 | 用户清缓存会丢失 | 做账号或云端历史时 |
| V1 数据样本来自 TikTok | 渠道迁移风险仍在 | 补采 Facebook、YouTube、Pantip 后 |

### 停止扩大投入的信号

- 用户进入页面但很少提交长文本。
- 用户看完结果但几乎不保存、不分享、不继续追问。
- 继续追问点击存在，但等待名单或付费意愿很低。
- 用户反馈认为结果只是普通 AI 安慰，缺少占卜语境价值。
- 泰语本地化反馈出现明显冒犯或不自然。
