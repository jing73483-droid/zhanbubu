## 9. 错误处理与兜底策略

### 错误分类

| 错误类型 | 触发条件 | 处理方式 | 用户提示 | 恢复策略 |
|---------|---------|---------|---------|---------|
| 输入为空 | 未填写问题 | 阻止提交 | 泰语提示用户写下当前感受 | 保留在输入页 |
| 输入过短 | 泰文有效字符不足 | 阻止提交 | 泰语提示用户多写一点 | 聚焦输入框 |
| 非泰语输入 | 泰语比例明显不足 | 阻止提交 | 泰语提示当前版本只支持泰语 | 允许修改后重试 |
| AI 服务超时 | 超过 30 秒 | 中断请求 | 泰语提示暂时没有生成完成 | 提供重试按钮 |
| AI 服务错误 | API 返回错误 | 捕获错误并记录 | 泰语提示服务暂时不可用 | 提供重试按钮 |
| AI 输出格式错误 | JSON 校验失败 | 自动重试一次 | 重试失败后展示兜底文案 | 用户可重新提交 |
| API Key 无效 | 服务端鉴权失败 | 记录配置错误 | 对用户显示服务维护提示 | 管理员检查环境变量 |
| 数据库写入失败 | Supabase 写入失败 | 不阻断已生成结果 | 提示保存可能失败 | 本地临时保留结果 |
| session 不存在 | 结果页 ID 无效 | 展示空状态 | 提示结果不存在 | 返回首页 |
| 等待名单提交失败 | 网络或服务端错误 | 保留表单内容 | 提示稍后再试 | 允许重试 |

### 全局错误边界

- 根布局配置 React Error Boundary。
- 页面级错误展示“回到首页”和“刷新页面”两个动作。
- 错误边界不展示技术栈细节、堆栈、API Key 信息。

### Loading 状态规范

| 场景 | Loading 方式 | 持续时间预期 | 超时处理 |
|------|-------------|-------------|---------|
| 提交输入 | 按钮禁用 + 短文案反馈 | 1 秒内 | 仍未响应则进入生成等待 |
| AI 生成 | `ReadingStream` 陪伴式等待 + 可取消 | 8 到 30 秒 | 30 秒后显示重试 |
| 结果页读取 | 页面骨架 | 1 到 3 秒 | 读取失败显示空状态 |
| 等待名单提交 | 表单按钮提交中 | 1 到 5 秒 | 失败后恢复按钮 |

### 空状态设计

| 页面/组件 | 空状态文案 | 引导动作 |
|----------|-----------|---------|
| 首页无草稿 | 泰语引导用户选择当前状态 | 选择第一个状态 |
| 结果不存在 | 泰语提示这次解读没有找到 | 返回首页重新生成 |
| 本地保存为空 | 泰语提示还没有保存的解读 | 回到首页开始一次解读 |
| 等待名单提交成功 | 泰语提示已收到，会优先通知 | 关闭弹层或复制当前结果 |

### AI 兜底文案原则

- 兜底文案必须承认系统暂时失败，不假装已经完成占卜。
- 兜底文案保留情绪承接，但不生成具体预测。
- 危机表达时，无论 AI 是否可用，都优先展示安全提示。

### 日志与隐私

- 服务端日志不打印完整用户问题，只记录 session ID、状态、错误码。
- 调试环境可以打印截断后的问题摘要，生产环境关闭。
- 等待名单联系方式不得出现在前端错误日志里。
